# Отчет: Шаг 3 — Заказы и двухэтапное резервирование

## Что сделано:
1. **Транзакционный эндпоинт заказов (`POST /api/orders`):**
   - Реализована изоляция транзакций через пулы PostgreSQL с блокировкой строк (`FOR UPDATE`), предотвращающая гонку данных при одновременных заказах.
2. **Двухэтапная логика резервирования:**
   - При оформлении заказа проверяется доступный остаток товара на складе (`stock_quantity - reserved_quantity`).
   - Если товара не хватает, транзакция прерывается с кодом `409 Conflict`.
   - При успешной проверке товар мгновенно замораживается в поле `reserved_quantity`, а позиции записываются в `order_items` с фиксацией актуальной цены.
3. **Фиксация суммы:** Автоматический расчет и обновление общей стоимости заказа (`total_amount`).
